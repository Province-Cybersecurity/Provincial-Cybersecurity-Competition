01 为什么做巡安

安全巡检不该只给出
一个吓人的结论

真实的网站安全检查，需要回答四个问题：发现了什么、在哪里发现、为什么值得关注、接下来怎样处理。

巡安把每条结果都绑定到来源页面和脱敏证据，并保留规则版本与扫描时间，让队员、老师和评委能够复核过程，而不是只能相信一句“存在风险”。

先确认授权，再开始巡检；先保留证据，再解释风险。

03 核心能力

关注这一次发生了什么变化

相同目标可以保存一次结果作为基线。后续巡检会区分新增、持续和已消失线索，帮助团队把注意力放在变化上。

  • 新增风险优先显示

  • 适合定期巡检演示

BOUNDARY

目标必须命中允许列表。巡检限制页数、深度和超时时间，不执行脚本、不提交表单、不尝试利用漏洞。

  • 严格目标允许列表
  • 限制深度和页面数量

05 部署与接入

从本地运行，到比赛展示

下面的四个步骤分别解决后端运行、外网访问、恒脑配置和静态展示。复制命令即可按顺序完成。

STEP 01 · LOCAL

在电脑上启动巡安服务

下载代码后进入仓库目录，使用 Python 启动服务。浏览器访问本地地址，先完成一次合成目标巡检。

Terminal
python3 -m xunan

检查点 访问 http://127.0.0.1:8765，确认首页和健康检查可以打开。

STEP 02 · SERVER

把巡检后端放到可访问的服务器

恒脑需要通过 HTTPS 访问巡安 API。请在服务器设置访问密钥、公开地址和授权目标，再启动服务。

Environment
export XUNAN_API_KEY='至少24位随机密钥'
export XUNAN_PUBLIC_ORIGIN='https://scanner.example'
export XUNAN_ALLOWED_TARGETS='https://authorized-demo.example/'
python3 -m xunan --host 0.0.0.0 --port 8765

检查点 只把经过授权的演示站点加入允许列表，密钥不要写入公开仓库。

STEP 03 · HENGNAO

让恒脑智能体调用真实工具

在恒脑创建智能体，导入项目提供的 OpenAPI 契约，配置服务地址和 X-API-Key，再添加系统提示词。

  1. 1导入 docs/hengnao-openapi.yaml
  2. 2配置公网 HTTPS 服务地址
  3. 3为请求头设置 X-API-Key
  4. 4分别试运行创建、查询、报告工具
  5. 5保存成功调用截图作为联调证据

检查点 智能体回答中的编号、风险数量和证据应与 API 返回一致。

STEP 04 · PAGES

用 GitHub Pages 发布项目展示页

本页面由仓库中的工作流自动部署。推送 demo-target/ 目录后，GitHub 会重新构建并发布静态站点。

  1. 1进入仓库 Settings → Pages
  2. 2将 Source 设为 GitHub Actions
  3. 3推送页面代码到 main 分支
  4. 4在 Actions 中等待绿色完成标记
  5. 5打开 Pages 地址检查电脑和手机显示

说明 GitHub Pages 只托管介绍页和合成测试素材；Python 巡检后端仍需单独部署。
